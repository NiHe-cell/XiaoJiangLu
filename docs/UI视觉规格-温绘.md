# 《骁将录：三国志》UI / 视觉规格（可直接驱动编码）

> 作者：温绘（实验室视觉支柱）｜版本：v1.0｜对象：Cocos Creator **3.8.8** / 微信小游戏 / 竖屏 **720×1280** fitHeight
> 事实源：`GAME.md` + `卡牌游戏大纲.md`
> **硬约束**：零外部美术资源（无贴图 / 无图集 / 无 Spine / 无自定义字体 / 无音频文件）。全部视觉由 `Graphics`（纯色 / 线 / 圆 / 圆角矩形 / 多边形）+ `Label`（系统字体）+ `Sprite.color` 程序化绘制。
> 本规格中所有坐标均可被代码直接 `node.setPosition()` 使用。

## 坐标系与通用常量（读我）

- **坐标系**：Cocos 节点坐标，**原点在画布中心**。屏幕范围 `x ∈ [-360, 360]`，`y ∈ [-640, 640]`。
- 与「左上角坐标」换算：`TL.x = x + 360`，`TL.y = 640 - y`。
- **可见安全宽度**（9:19.5 机型）≈ 591 → 半宽 ≈ 295。**所有可点击元素的左右边缘必须落在 `x ∈ [-290, 290]`**。
- **背景层**（纯装饰、无交互）可用 Widget 左右拉伸到 `±360`，不受 ±290 限制。
- **热区下限**：所有可点击元素 ≥ **44×44**（本规格实际取值 ≥ 48；唯二贴下限的是「货币 chip 52」与「公告条 48」，均已在 §6 标注 ✅）。
- **相邻热区间隙 ≥ 12px**（防误触），最小不得 < 8px。
- **拇指区**：屏幕下半 60% = `y ≤ 128`。高频操作（主导航、主 CTA、战斗指令）必须落在其中；低频/结果类可例外并在表中标注。

## 1. 视觉调性与关键词

### 1.1 情绪板（纯文字描述）

**一句话**：夜里点了灯的东汉末年戏台 —— **暖金灯火 + Q 版大头武将 + 硬边 Sony 风描边**，热闹、明快、不阴森。

- **色感**：以「暖金 #F5C451」为第一记忆色贯穿全局（按钮、标题、星级、太阳纹），底色用**低饱和靛青**（`#1E2A3C` → `#2C3B52`）压住画面让金色跳出来。避免使用大面积纯黑与惨白：黑只用在蒙版渐变，白降级为米宣纸色 `#F2EADC`。整体是「**暗底 + 灯火金 + 阵营彩**」的三层结构。
- **质感**：**平涂 + 硬描边**。所有元素 = 面块 + 2~4px 深色描边 + 顶部 1~2px 高光边（模拟纸雕/木刻）。**禁止渐变投机**：需要层次时用「两块纯色上下拼接 + 中间 2px 亮边」，而不是线性渐变（Graphics 不支持渐变，且省 draw call）。
- **形状语言**：一切卡片是 **圆角矩形（r=20）**；图标是 **几何化的兵器/符号**（交叉刀、盾、菱形符文、十字光环），能在 88×88 里一眼认出。**没有曲线写实的部件**。
- **节奏**：静态时「稳」（对称、居中、横向 grid 对齐）；触发时「炸」（scale punch + 位移 + 短震动 + 飘字）。判读一句话：**安静时像商店货架，打起来像老虎机**。
- **Q 版萌系落点**：战场单位头身比 **1 : 1.6**（大头、小手），眼睛是 **2 个纯黑圆点 + 1 个高光点**，受击时 face 层切替换素材为「> < 眼」。这是唯一允许的"萌"表达，不做表情贴图。
- **参照**：《放开那三国》的**信息密度与金色主调**，但把它压进竖屏单手：更少层数、更大按钮、更强中心对称。

### 1.2 三条不可妥协的视觉红线（违反即打回）

| # | 红线 | 判据 |
|---|---|---|
| **R1 · 零资源** | 任何视觉元素**不得**依赖 `Sprite.spriteFrame` 外部贴图、图集、Spine、位图字体、TTF。只允许 `Graphics` 矢量绘制 + `Label`（系统字体）+ `Sprite` 纯色/九宫格纯色。 | 全工程 `assets/` 下不得出现 `.png/.jpg/.atlas/.plist/.sk/.ttf/.mp3` |
| **R2 · 安全区与拇指区** | 所有可点击元素 **左右边缘 ∈ [-290, 290]** 且 **尺寸 ≥ 44×44**；**高频操作中心 y ≤ 128**；相邻热区间隙 ≥ 12px。 | `docs/UI视觉规格-温绘.md` §6 热区总表逐行自证 |
| **R3 · 可读性与反馈** | 正文与底色对比度 **≥ 4.5:1**；最小字号 **≥ 18**，正文 **≥ 26**；**任何可点击元素在被按下后 ≤ 100ms 内必须出现可见反馈**（下沉 4px + 明度 -12% 起步），永不出现"点了没反应"。 | §3 对比度表；§7 状态表；§9 反馈表 |

## 3. 字体与字号阶梯

### 3.1 字体实现口径

- Cocos 3.8.8 的 `Label` **不指定 `font` 资源**时走默认系统字体。微信小游戏 iOS/Android 均能渲染中文。
- **粗体**：`label.isBold = true`（渲染层加粗，无需字体文件）。仅允许在 `h1/h2/FS.btn/FS.num` 四档使用。
- **描边**：`label.enableOutline = true; label.outlineColor = hex(LINE); label.outlineWidth = 2;`（战斗飘字 `outlineWidth = 3`）。**所有出现在非纯色底上的文字必须开描边**。
- **阴影**：`label.enableShadow = true; label.shadowColor = hex(BG_DEEP); label.shadowBlur = 2;`（`h1/h2` 与飘字启用）。
- **行高**：`label.lineHeight = fontSize * 1.35`。**溢出处理**：`label.overflow = Overflow.SHRINK`；数值类固定宽发行右对齐，禁止换行。
- **唯一禁止**：不得设置 `label.font = <任何 TTF/BitmapFont>`。

### 3.3 文字对齐与长度上限约束

- 面板标题居中，最多 **7 个汉字**，超出用 `Overflow.SHRINK`。
- 武将名最多 **4 字**（`#FFF` 不缩写，用 SHRINK 到 26）。
- 技能描述最长 **48 字**，区块内滚动，不撑破面板。
- 数字类一律 `HorizontalAlign.RIGHT` + 千分位（≥10000 显示 `1.2万`）。

### 6.8 热区自检 Q&A（写给工程师）

- **Q：TabBar 背景宽 720 超出 ±290 怎么办？**  
  A：背景是 `Graphics` 绘制的**无交互**节点（不挂 `BlockInputEvents`、不挂 Button），不受约束；**只有它的子节点图标按钮**（120×132）才是热区，图标本体 φ72 右缘 276 ✅。
- **Q：横向 ScrollView 里的第 7、8 个槽会被 mask 裁掉一部分还算法吗？**  
  A：被 mask 裁剪后的**可见部分**才是有效热区。第 7/8 槽滚动进入后可见部分 ≥ 88×88 才算达标；初始状态下不算（标注「滚动后出现」）。
- **Q：列表行 h=104 但间距只有 8，会不会误触？**  
  A：行按钮与行内子按钮不重叠（子按钮独占右侧 132×64 区），父行点击区与子按钮区互斥（**子按钮优先响应**），实现时给子按钮更高 `priority`。

## 9. 动效规格（全部可 `tween` 直接实现）

> **统一约定**：所有 tween 目标必须是**子节点局部变量**（`position` / `scale` / `uiOpacity`），不要动父容器的世界坐标。
> 所有 `duration` 都必须乘以 `SpeedScale`（1x=1.0 / 2x=0.5 / 3x=0.34）。
> 单位：位移 **px**，时长 **秒**（Cocos tween 用秒缓动名：`'quadOut' | 'quadIn' | 'backOut' | 'backIn' | 'sineInOut' | 'cubicOut' | 'elasticOut'`）。

### 9.1 面板入场 / 出场

| 场景 | 参数 |
|---|---|
| **全屏面板进入** | `position.y: from -60 → 0`，`uiOpacity: 60 → 255`，`0.28s`，`quadOut`；同时暗幕 `0 → 180` 同参数 |
| **全屏面板退出** | `position.y: 0 → -40`，`uiOpacity: 255 → 0`，`0.22s`，`quadIn`；退出期间**禁止该面板内所有按钮再次点击**（`node.interactable = false`） |
| **弹窗（小面板）进入** | `scale: (0.86,0.86) → (1,1)`，`0.26s`，`backOut`（overshoot 1.4）；暗幕同步 |
| **弹窗抖动关闭（点了外部）** | `scale: 1 → 1.04 → 1`，`0.16s` 后整体消失；**同时**播放 mask 反向 fade |
| **Tab 内容切换** | 旧内容 `x: 0 → -40, opacity → 0`，`0.14s quadIn`；新内容 `x: 40 → 0, opacity → 255`，`0.20s quadOut`，延迟 0.10s 开始 |

### 9.2 单位 / 卡牌类

| 场景 | 动画序列（顺序执行） |
|---|---|
| **受击** | ① 位移 shake：连续 3 次 `to(0.04, {position: (x ± 8, y)})`（共 0.12s，`linear`）② 白闪叠加层 alpha `0→140→0`，0.10s ③ 同步 scale `1 → 0.96 → 1`，0.12s |
| **暴击受击** | shake amplitude **12px**、6 次（0.18s）；额外把 camera shake 设为 8px |
| **阵亡** | ① 卡 rotation `0 → -8°` + `uiOpacity 255 → 140`，`0.30s quadOut` ② 下坠 `position.y -= 24`，`0.24s quadIn` ③ 覆盖 ✕ 图标 scale `0 → 1.15 → 1`，`0.20s backOut`（延迟 0.12s） |
| **满怒呼吸** | 无限循环：`to(0.45,{scale:(1.06,1.06)})` → `to(0.45,{scale:(1,1)})`，`sineInOut`，`repeatForever`；仅在怒气=100 时启动，怒气被消耗即 `.stop()` |
| **选中/待出手** | 头顶 ▼ 箭头：`to(0.35,{position:(x, y+10)})` ↔ `to(0.35,{position:(x,y)})`，`sineInOut`，`repeatForever`；±10px |
| **卡片入手（招募结果）** | ① scale `0.2→1.15` `0.24s backOut` ② rotation `-12°→0` `0.2s` ③ 卡面扫光：一条宽 40 的斜向白色 A=120 矩形从左上扫到右下 `0.36s` ④ 品质边框炸开一次 alpha `180→0` `0.3s` |
| **上阵/换槽** | ① 原槽位卡 scale `1→0.8` + opacity `→0` `0.14s quadIn` ② 目标槽位从 scale `0.8` + `y-20` 补入 `0.22s backOut` ③ 目标槽外框 `GOLD` 闪一下（alpha 0→200→0，0.3s） |

### 9.3 数值 / 元件类

| 场景 | 参数 |
|---|---|
| **数字滚动**（战力、伤害总量） | 每次数值更新时用 `lerp(old, new, t)` 插值：`to(0.5, {}, { onUpdate: (tw, ratio) => label.string = fmt(lerp(from, to, ratio)) })`，缓动 `quadOut`；**必须在 0.5s 内完成，最长不超过 0.8s** |
| **血条扣减** | 先白色 "残影条" 在原宽度停留 0.18s，然后 tween 到新宽度 `0.26s quadOut`；真实血条延迟 `0.10s` 再缩到目标宽度 `0.26s quadOut`（两段的双条落差感＝打击感的来源） |
| **按钮按下** | `scale: 1 → 0.96` + `position.y -= 4`，`0.08s quadOut`；抬起 `0.12s quadOut` 回位 |
| **按钮禁用→可用** | 底色 `TXT_3 → 正常`，`0.3s`；附带一个一次的 scale `1 → 1.06 → 1` 提示玩家"它活了" |
| **红点/角标出现** | scale `0 → 1.3 → 1`，`0.24s backOut`；持续在时需要每 2s pulse 一次 `1 → 1.12 → 1`（0.4s），**红点 ≤ 3 个同时存在**（过多即失去意义） |
| **Toast** | 从 `y: 260`（Home onChange 上方）淡入 `0.2s`，停留 1.2s，淡出 `0.3s`；连续 Toast **队列化**，禁止叠 3 条以上 |

### 9.4 屏幕级 juice

| 场景 | 参数 |
|---|---|
| **相机 shake（轻）** | amplitude 6px，8 次，`0.16s`；用在普攻 |
| **相机 shake（中）** | amplitude 12px，8 次，`0.20s`；用在必杀 |
| **相机 shake（重）** | amplitude 14px，10 次，`0.24s`；用在合击 / BOSS 出现 |
| **屏幕ছায়া yeah 闪白** | 全屏白 Rect alpha `0 → 90 → 0`，`0.14s`；仅在合击/胜利使用 |
| **关卡通过（三星判定）** | 星 1/2/3 依次：延迟 `0 / 0.22s / 0.44s`，每颗 scale `0 → 1.5 → 1` `0.34s backOut` + 伴随银色星芒爆（4 条 `STAR` 短射线，0.2s） |
| **胜利** | 背景整体 brightness 提升（用一层 `GOLD` A=0→40→16 的叠加 Rect 代替后处理），文字从 scale 1.6 砸下 `0.34s backOut` + 屏幕轻 shake 6px |
| **失败** | 背景降一等：叠加 `BG_DEEP` A=0→120 `0.4s`；文字从 scale 1.15 沉下 `0.4s quadOut`，**不做 shake**（失败的反馈应该"重"，不与胜利的"炸"混淆） |

### 9.5 动效禁令（防性能 / 防眩晕）

1. 禁止 `repeatForever` 超过 **6 个并行存在**（主城里主角 + 2 个 pulse 上限）。
2. 所有 Graphics 不要在 tween `onUpdate` 里重画复杂路径 —— 只动 `position/scale/opacity/color`。
3. **禁止**入场动画总时长 > 0.5s（玩家的等待忍耐闸）；**例外**：结算页「结果 → 星级 → 按钮」的连续演出允许放宽到 1.2s。
4. 倍速 3x 时 **关闭** 所有 `repeatForever` 的呼吸/光环（省 draw + 减少眩晕）。

## 10. 音效清单（零音频资源下的降级方案）

### 10.1 实现约定（工程接口）

> **零资源约束下，当前版本全部音效降级为「视觉 + 触觉」。但接口必须先埋好**，后续放入 `assets/resources/audio/*.mp3` 时零改代码。

```ts
// assets/scripts/core/audio/AudioBus.ts —— 埋点先占位，资源后补
type SfxName = 'ui_tap' | 'ui_back' | 'battle_hit' | /* ... */ 'gacha_ten';

export class AudioBus {
  private static _cache = new Map<string, InnerAudioContext>();
  static enabled = true;

  static play(name: SfxName, vol = 1) {
    if (!this.enabled) return;
    const path = `audio/${name}`;
    resources.load(path, AudioClip, (err, clip) => {
      if (err) { AudioBus.fallback(name); return; }   // 资源缺失 → 静默走降级
      cc.audioEngine.play(clip, false, vol);
    });
  }

  /** 无音频资源时的降级：震动 + （可选）视觉补丁 */
  static fallback(name: SfxName) {
    const profile = SFX_TABLE[name];
    profile.vibrate && wx.vibrateShort?.({ type: profile.vibrate as any });
  }
}
```

**降级三原则**：
1. **任何原本有音效的地方，必须有可见可感的替代反馈**（屏幕震动 / 白闪 / 数字弹出），这是红线 R3 的音频分支 —— 「点了没反应」比「没声音」严重 10 倍。
2. 震动不可滥用：**同屏 200ms 内只允许触发 1 次**（`AudioBus` 内加节流），否则手感发麻且耗电。优先级：合击 > 必杀 > 招募成功 > 普攻 > UI 点击。
3. **UI 点击类一律不震动**（会烦），只做视觉按下反馈；震动只保留给「战斗打击」与「获得奖励」两类情绪峰值。

### 11.2 L1 · 24 专属主色（代码生成，不用手写色表）

```ts
// assets/scripts/core/ui/HeroPalette.ts
// ⚠️ HUES 是 frozen table：改这里 = 改全局所有武将的颜色。改之前先跑一遍 assertHueSpread()。
export const HUES = [20,157,295,72,210,347,125,262,40,177,315,92,
                     230,7,145,282,60,197,335,112,250,27,165,302] as const;  // 黄金角 137.5° 分布

/** 主色 = HUES[visualIdx] 的纯查表。★ 绝对不要在运行时做色相偏移，见下方说明 */
export function heroMainColor(visualIdx: number): Color {
  return hsl2rgb(HUES[visualIdx % 24], 0.62, 0.56);
}

export function hsl2rgb(h: number, s: number, l: number): Color {
  const c = (1 - Math.abs(2 * l - 1)) * s;
  const x = c * (1 - Math.abs(((h / 60) % 2) - 1));
  const m = l - c / 2;
  let r = 0, g = 0, b = 0;
  if (h < 60)       { r = c; g = x; }
  else if (h < 120) { r = x; g = c; }
  else if (h < 180) { g = c; b = x; }
  else if (h < 240) { g = x; b = c; }
  else if (h < 300) { r = x; b = c; }
  else              { r = c; b = x; }
  return new Color(Math.round((r + m) * 255), Math.round((g + m) * 255), Math.round((b + m) * 255));
}

/** 开发期自检：任一阵营内最小色相间隔 < 30° 就报警。DEV 模式下 UnitView 初始化调用一次 */
export function assertHueSpread(list: { name: string; camp: number; visualIdx: number }[]) {
  const groups = new Map<number, number[]>();
  list.forEach(h => groups.set(h.camp, [...(groups.get(h.camp) ?? []), h.visualIdx]));
  let worst = 360, worstPair = '';
  for (const [camp, idxs] of groups) {
    for (let i = 0; i < idxs.length; i++) for (let j = i + 1; j < idxs.length; j++) {
      const d = Math.abs(((HUES[idxs[i]] - HUES[idxs[j]] + 540) % 360) - 180);
      if (d < worst) { worst = d; worstPair = `${idxs[i]}/${idxs[j]} @camp${camp}`; }
    }
  }
  if (worst < 30) console.warn(`[HeroPalette] 同阵营色相过近：${worstPair} 仅 ${worst.toFixed(2)}°（要求 ≥30°）`);
  return worst;
}
```

- **固定 S=0.62 / L=0.56**：明度锁死，避免某些武将"看起来更亮 = 更强"的错误直觉。
- **`visualIdx` 的取色落位由 `HeroConf.ts` 负责**（已用禁边图 + 阵营容量约束精确求解），实测最差间隔：蜀 32.46° / 魏 32.46° / 吴 64.92° / 群 52.52°，全部 ≥ 30°。
- **★ 已删除「与阵营色过近则 runtime +40°」的守卫 Brotion：我当初写的那个守卫会破坏文辞的求解结果**（A 不偏移、B 偏移 40° 时，原本 32° 的两人可能塌到 8°）。

- **禁止任何人再往 `heroMainColor()` 里加 if**：颜色必须可静态预测，否则设计侧调色板时无法预判结果。

### 11.6 Q 版身体通用画法（所有单位共用，仅主色/头饰不同）

```
// 单位局部坐标，原点＝卡中心 (0,0)，卡 150×180
const SK = '#F3D3B0';                       // 肤色
const OUT = LINE;                           // 描边统一 #40536F, lineWidth 2

// 1) 披风（在最底层）
fill(主色暗 30%); moveTo(-46, -34) → lineTo(-40, 6) → lineTo(40, 6) → lineTo(46, -34)
                 → quadraticCurveTo(0, -48, -46, -34) → close → fill()

// 2) 身体（梯形）
fill(主色); moveTo(-34, -40) → lineTo(34, -40) → lineTo(42, 26) → lineTo(-42, 26) → close → fill()
stroke(OUT, 2)

// 3) 胸前阵营色宽带（第二层辨识）
fill(阵营色); roundRect(-20, -34, 40, 9, 4) → fill()

// 4) 双臂（两个小圆角矩形，垂在身体两侧）
fill(主色); roundRect(-52, -22, 18, 40, 9) 与 roundRect(34, -22, 18, 40, 9) → fill()

// 5) 手（肤色小圆）
fill(SK); circle(-43, -26, 9); circle(43, -26, 9) → fill()

// 6) 头
fill(SK); circle(0, 30, 28) → fill(); stroke(OUT, 2)

// 7) 眼（默认：两点 + 高光）
fill('#2B2B33'); circle(-11, 34, 5); circle(11, 34, 5) → fill()
fill('#FFFFFF'); circle(-12, 36, 2); circle(10, 36, 2) → fill()   // 左上角高光

// 8) 嘴（默认：小弧）
stroke('#2B2B33', 2.5); arc(0, 22, 8, 200°, 340°) → stroke()

// 9) 脸颊腮红（萌系落点，唯一允许的装饰）
fill('#F09A9A', A=90); circle(-19, 22, 6); circle(19, 22, 6) → fill()
```

**受击时「> < 眼」替换**（只需替换步骤 7 的两行，其余不重画）：

```ts
  // 右眼 "<"

}
```
