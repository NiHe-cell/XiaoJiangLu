## 1. 回合流程时序

```
构造 BattleCore(units, seed)
   └─ 复制 Unit（外部对象是初始值模板，战斗状态一律读 core.get(uid)）
   └─ 回合 lock 计算出手序
循环：
  uid = core.next()            // -1 = 结束
   ├─ 本回合还有未行动且存活的单位 → 返回它（同一 uid 在 act 之前重复调用会返回同一个）
   ├─ 本回合走完 → round++，全体 buff 回合数 -1（turns=0 永久 buff 不减），重置行动标记，重排出手序
   └─ round > maxRound(30) → 按剩余血量百分比判胜，end 事件进 pending
  evs = core.act(uid, useSkill)   // 返回按发生顺序的事件序列
   └─ [turn] → [atk | skill] → [buff...] → [rage...] → [die...] → [end?]
  core.isEnd() → core.winner() → 结算
合击（随时可由玩家点击，不占用回合）：
  core.readyCombos() → [bondId...]；core.tryCombo(bondId) → Ev[] | null
```

**一次 act 内部的严格顺序**（表现层可以按这个顺序排动画）：
1. `turn` — 标记谁开始动
2. `skill` / `atk` — 本次行动的主事件，**伤害已在数据层结算完**（UI 只是回放）
3. `buff` — 技能的增减益
4. `rage` — 本次行动引发的怒气变化（含施法清空、出手获得、受击获得、击杀获得）
5. `die` — 血条归零
6. `end` — 一方全灭

> 关键设计：**怒气技先清空怒气再结算**（`-rageMax` 事件在 `skill` 事件之前），随后才 `+rageOnAttack`，所以放完大招的人不会残留满怒。

## 2. 出手顺序（速度决定）

- 排序键：**速度降序 → slot 升序 → side 升序 → uid 升序**（完全确定，同速不会出现随机抖动）。
- **每回合开始时算一次并锁定**。回合中途的速度增减益（如诸葛亮八阵图 -25% 速）**要下一回合才生效**。
  > 这是刻意设计：若每次都重排，一个被减速的单位可能在同一回合被跳过，或被加速的单位一回合动两次，这是回合制最经典的脏 bug。
- 已阵亡单位自动跳过；本回合已行动的单位（含玩家手动点、合击主攻手之外的所有人）也不会重复出手。

## 3. 站位与目标选择

站位 `slot` 0-5，**slot < 3 为前排**（UI 3×2 阵列，前排在中线两侧）。

| 目标规则 | 选取 | 用于 |
|---|---|---|
| `enemyFront` | 敌方前排（slot<3）中**当前血量最低**者；前排全灭则打后排最低者 | 普攻、多数单体怒气技 |
| `enemySingleLow` | 敌方中当前血量百分比最低者 | 赵云、黄忠、人中吕布合击 |
| `enemyAll` | 敌方全体存活单位 | AoE 怒气技 / 多数合击 |
| `allyLowest` | 我方当前血量百分比最低者（含自己） | 刘备、小乔单体治疗 |
| `allyAll` | 我方全体存活单位 | 群奶 |
| `self` | 自己 | 许褚、董卓自增益 |

**每次选择都按当前战场重新计算** → 多段技能（如赵云 4 段）在某一段打死目标后会自动转火下一个目标，不会出现"打尸体"的空段。前排集火永远优先咬当前血量最低者，这让**坦克的存在有意义**（玩家把坦克摆前排=主动吸引集火）。

## 4. 伤害 / 暴击 / 治疗公式（`Balance.ts`）

```ts
// 防御折算：永远为正，不会出现负血与除零
factor = DEF_K / (DEF_K + def)            // DEF_K = 500，下限 MIN_DEF_FACTOR = 0.15
伤害   = max(1, round( atk × ratio × factor × rand(0.95~1.05) × (crit ? 1.6 : 1) × typeCounter ))
治疗   = round( (目标最大生命 × ratio × 0.22 + 施法者攻击 × ratio × 1.2) × rand(0.97~1.03) )
```

- **多段不过载**：`perHit = atkRatio / hitCount`。SkillConf 注释写明"多段用于手感"，所以多段改变的是**表现与方差**（每段独立掷暴击和浮动），不是数值总量。否则 5 段的五虎齐鸣会碾压所有单段技能。
- **伤害类型**：`role === 2`（法攻）打 `mdef`，其余打 `pdef`。合击由"主攻手"（成员中攻击最高者）的 role 决定。
- **暴击率**：`clamp(0.08 + 技能critBonus + 暴击buff, 0, 0.75)`，倍率 1.6。
- **软克制**（大纲要求的"软"克制，正负 10%）：法攻 → 防御 → 物攻 → 辅助 → 法攻 四型循环。只影响期望 μ，不改变胜负格局。
- **治疗以目标最大生命为主词条**（§11 结论 3 有实证）：只按攻击算的话辅助一口奶不到坦克血量的 5%，辅助等于不存在。
- **单次伤害保底 1**：避免极端防御配装下"点了没反应"。

## 5. 怒气规则

| 事件 | 获得 | 备注 |
|---|---|---|
| 出手（普攻 / 怒气技 / 纯治疗技） | +30 | 保证辅助不靠挨打也能攒满 |
| 受到伤害 | +12 | 一次行动内对同一目标只结算 1 次（多段不会刷怒） |
| 击杀 | +25 | 滚雪球奖励 |
| 释放怒气技 | 清零，返还 `rageOnSkill = 0` | 放完后仍有本回合的 +30 |
| 羁绊合击 | 全成员清零 | 代价就在这里 |

- 上限 100，开局 0（`BAL.rageInit` 留作旋钮，默认不给）。
- 节奏实测：**第 3 回合约 60% 的角色满怒**（每回合 +30，加上挨打 +12），第 6 回合左右能放第二次。交替普攻 + 大招的节奏符合"单场 0-30s"的手感目标。
- 满怒后**由表现层决定何时放**：手动模式点头像释放，超时 8 秒默认普攻（怒气保留）；自动模式 `useSkill=true` 直接放。纯治疗技在全队血量 > 82% 时 AI 会攒着不放（避免空奶）。

## 6. 羁绊合击规则

- 触发条件：羁绊成员**全部上阵 + 全部存活 + 全部满怒**。
- 攻击基数：`Σ(成员有效攻击) × 0.65`。之所以要乘系数：合击同时消耗 2-5 个人的满怒，攻击力直接相加会让合击碾压一切。
- 数值定位：合击应该是**总输出 ≈ 单人怒气技的 1.5-2.5 倍，但打全体**。实测桃园/五虎/赤壁类合击对 4 人敌阵的总输出约为单人技能的 2.4 倍，且附带群体减益 —— 符合大纲"翻盘关键"的定位。
- **不消耗回合**：合击后主攻手本回合仍能正常出手（与已集成的 BattlePanel 行为保持一致）。代价是全员怒气清零，且要全员活到那一刻。
- `bondId` 冲突说明：一个武将可能属于多个羁绊（如关羽属于桃园/五虎/刮骨），`readyCombos()` 按 BondConf 实际成员判定，不依赖 `Unit.bondId`。

## 7. 事件协议（`Ev`）

| 事件 | 字段要点 |
|---|---|
| `turn` | `round` 是当前回合数（1 起） |
| `atk` | 单体普攻，`dmg` `crit` |
| `skill` | `to/dmg/heal/crit` **四个数组并行，按"目标"聚合**：一个目标一条，不是一"段"一条。需要多段飘字时，用 `getSkillConf(e.skillId).hitCount` 把该目标的伤害拆成 N 段播 |
| `combo` | 接口固定只有 `dmg` 数组；**治疗型合击的回复走独立的 `heal` 事件**，`dmg` 对应位置填 0 |
| `buff` | `value` 是原始配置值（负数=减益），`turns=0` 表示永久 |
| `rage` | `val` 是**变化后的怒气值**，不是增量 |
| `die` | 该单位 `alive=false`、`buffs` 清空 |
| `end` | `winner` 0=我方 1=敌方 |

> ⚠️ 超时结束的 `end` 可能由 `next()` 内部触发（`for` 循环无法返回事件），请调用 `core.pendingEvents()` 取走。**`act()` 开头会自动 flush 这个队列**，`isEnd()/winner()` 始终可用。

## 8. 星级与奖励

```ts
calcStars(rounds, dead)        // rounds=使用回合数，dead=我方阵亡人数
  3★ : dead === 0 && rounds <= 4
  2★ : dead <= 1 && rounds <= 7
  1★ : 其他（含超时判胜）
```
> 门槛按"捷径+零损","的知识三星不该靠运气，也不该靠碾压后的余兴 —— 它是**阵容成型度**的考试。当前实测三星率极低（见 §11 结论 8），这是刻意留的钩子，等实机阵容强于测试数据后自然开放。

```ts
stageEnemyLevel(chapter, index)   // (chapter-1)*8 + index + 1，与 StageConf.enemyLevel 一致（1-48）
stageEnemyCount(chapter, index)   // 3-6：章内越靠后越多，章节越深越多（第1-2章 3~5，3-4章 4~6，5-6章 5~6）
stageReward(chapter, index, level)// exp/silver 随章节×1.0~3.5、玩家等级、章内序号三段增长 + 将魂/精炼石/进阶丹/章末碎片
firstClearBonus(chapter, index)   // exp×2 silver×2 + 将玉（**将玉只从首通产出，无充值入口**，章末双倍）
staminaPerStage                   // 6
```

## 9. 防死循环策略（三层）

1. **回合上限 30**：`round > maxRound` → 比较双方 `Σ当前血/Σ最大血`，高者胜，**平局判守方（敌方）胜**（防止玩家在无奶阵容里躺着过图）。实测超时率 0.1-0.2%，不影响正常体验。
2. **`next()` 的 guard 循环**（上限 4096 次）：内部就一定不会出现"整轮全死导致偶数性死锁"。
3. **`autoBattle()` 的 maxSteps**（默认 4096）：自动/离线推演的硬闸。即使上述两层失效也不会卡住主线程。

互奶僵局的根因是**治疗效率 ≥ 输出效率**，唯一的平衡旋钮是伤害/治疗的相对强度，§11 结论 4 给了标定边界（DMG_SCALE 不能低于 2.5）。

## 11. 自测结论（1920 场 + 单场核对）

模拟口径：每关 40 局 × 48 关；我方阵容按章节进度假设（第1章开局默认 3 人 / 第3章桃园阵容 / 第6章五虎成型），**复刻 `Store.attrOf` 与 `Store.enemyAttr` 的真实公式**，双方同等级、无装备。

### 结论 1 — 不死循环 ✅
1920 场全部在有限步内结束。命中 30 回合上限的仅 0.2%（4 场），且都由 `forceEnd` 正常收尾，`isEnd()` → `winner()` 链路可用。

### 结论 2 — 无 NaN / 无负血 / 无超血 / 无怒气越界 ✅
每局结束后校验全部单位的 `hp/atk/rage` 有限性、`0 ≤ hp ≤ maxHp`、`0 ≤ rage ≤ 100`，并遍历事件流校验伤害与治疗非负：**异常计数 0**。

### 结论 3 — 平均回合 5.80，82% 落在 3-8 回合 ✅（达标）
```
2R×50  3R×497  4R×265  5R×353  6R×281  7R×168  8R×50  9R+×239（多为 30R 超时）
```
普攻平均打掉目标 **24.5% 最大生命**（约 4 刀一个人），这是"看得见血条在动，又不会被一刀秒"的手感区间。

### 结论 4 — DMG_SCALE 的标定边界（关键单点）
| DMG_SCALE | 平均回合 | 普攻占目标最大生命 | 超时率 | 判读 |
|---|---|---|---|---|
| 6.5（原值） | 3.60 | 44%+ | 0.0% | 双方被"一回合打穿"，1-2 回合占比 40%，三星率 0% |
| 3.5 | 5.07 | 28.8% | 0.0% | 略快 |
| **3.0（取定）** | **5.84** | **24.5%** | **0.1%** | **78% 落在 3-7 回合** |
| 2.5 | 6.86 | 20.4% | 1.4% | 奶量开始追平伤害 |
| 1.1 | 12.47 | 8.9% | 6.8% | 互奶僵局，不可用 |

### 结论 5 — 治疗公式必须换成"目标最大生命"为主词条
改之前（纯攻击 × 2.0）：场均我方阵亡 3.3 / 5 人，**从第 4 章起任何阵容都守不住**，辅助技能等于废牌。
改之后（22% maxHp + 1.2 攻击）：同样阵容场均阵亡降到 2.15-3.35，治疗系武将从"摆设"变成阵容必选项 —— 这才符合大纲"辅助维持队伍续航"的定位。

### 结论 6 — 胜负瓶颈不在伤害缩放，在敌方成长模型
把 DMG_SCALE 从 6.5 一路降到 1.1（伤害差 6 倍），**总胜率始终 52%-54%**。原因是双方等比缩放，缩放改不了相对强弱。真正变量是 §10 的 A 项：

| `enemyAttr` k 系数 | 总胜率 | 平均回合 | 场均阵亡 | 第6章胜率 |
|---|---|---|---|---|
| 0.06（现状） | 53.1% | 5.84 | 3.34 | 23% |
| **0.035（建议）** | **78.5%** | **4.98** | **2.15** | **64%** |
| 0.025 | 84.8% | 4.18 | 1.71 | 88% |

### 结论 7 — 第 1 章对新手阵容友好 ✅
第 1 章胜率 **97%**，平均 4.4 回合，场均阵亡 1.15。第 101 关（1 敌）平均 2 回合收场，正好做教学关。

### 结论 8 — 三星率极低，是有意留的难度钩子
分章汇总（DMG_SCALE=3.0、k=0.06 现状）：

| 章节 | 胜率 | 平均回合 | 场均阵亡 | 三星率 | 超时率 |
|---|---|---|---|---|---|
| 1 | 97% | 4.4 | 1.15 | 1% | 0.0% |
| 2 | 30% | 3.8 | 3.19 | 0% | 0.0% |
| 3 | 63% | 4.7 | 2.87 | 0% | 0.0% |
| 4 | 70% | 8.0 | 2.61 | 0% | 0.9% |
| 5 | 35% | 7.3 | 4.67 | 0% | 0.0% |
| 6 | 22% | 6.7 | 5.59 | 0% | 0.0% |

三星要求"零阵亡"，而当前同等级交战平均死 3 人 —— 这**不是**星规太严，而是阵容强度不足（见结论 6）。按 A 项修到 0.035 后阵亡降到 2.15，三星会随养成自然开放。

### 结论 9 — 合击与怒气技的出现频率合理
平均每场触发 **0-6.2 次合击**（第 4 章紧凑阵容最高），怒气技平均每场 **3-24 次**（超过 40 次的都是 30 回合超时场，正常场集中在 3-20 次）。合击不至于频繁到稀释仪式感，也不至于稀缺到玩家忘记有这个功能。

### 结论 10 — 多段与 AoE 不过载（数值，非手感）
多段过载检查：`五虎齐鸣` 是 0.65 系数 × 5 段 AoE。按"总量对齐"处理（每段 0.13）后，它的单人期望伤害低于关羽的单体 `青龙偃月`（2.6），但打 4 人敌阵时总输出是关羽的约 2.4 倍 + 群体破防 —— **合击的价值在"打面"而不是"打点"**，这正是设计的意图。
