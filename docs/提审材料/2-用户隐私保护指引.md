## 0. 结论先行（纠正一个常见误解）

> ❌ **错误认知**：在 `game.json` 里加 `"__usePrivacyCheck__": true` 就能开启隐私校验。
>
> ✅ **正确**：`__usePrivacyCheck__` 是**小程序 `app.json`** 的字段。微信官方《小游戏配置》字段表中**没有这个字段**（2026-10-02 核实，字段仅含 `deviceOrientation`/`desktopDeviceOrientation`/`showStatusBar`/`networkTimeout`/`workers`/`subpackages`/`parallelPreloadSubpackages`/`navigateToMiniProgramAppIdList`/`permission`/`openDataContext`/`resizable`）。
>
> 小游戏的隐私合规路径是 **两条腿**：
> 1. **后台**：mp 微信公众平台 → 设置 → 服务内容声明 / 用户隐私保护指引 → 填写并**提交审核通过**
> 2. **代码**：调用 `wx.getPrivacySetting` 判断状态 → 用 `wx.requirePrivacyAuthorize` 或 `wx.onNeedPrivacyAuthorization` 弹窗 → 用户同意后才能调隐私接口

本项目的 `game.json` **不需要、也不应该**添加 `__usePrivacyCheck__`。

### 1.1 关于 `wx.login` 的口径（重要）

`wx.login` 返回的 `code` 本身**不含用户信息**。本项目的用法是：

- **当前实现**：无服务端 → `code` 拿到后**不上送任何服务器**，因此实际上**不产生个人信息处理行为**。
- **若后续接服务端**：`code` 换取 `openid` 属于个人信息处理，**必须在隐私保护指引中勾选「微信登录 / openid」并说明用途**。

> 📌 **给主理人的口径建议**：提审阶段对外表述统一为「**静默登录，仅用于标识存档归属，不获取您的昵称、头像、手机号等个人信息**」。只要代码里确实没有 `code2session` 上行，这个表述就是真实的，且能通过审核。

### 1.2 关于广告 SDK 的口径（2026 新增要求）

2026 年起，**广告组件采集设备信息用于广告投放也需在隐私保护指引中声明**。本项目是纯 IAA 变现，因此必须勾选设备/广告标识相关项——**不勾选反而会因"指引与实际调用不一致"被驳回**。

## 3. 代码侧接入点位清单（给实现线）

> 当前 `assets/scripts` 中 `wx.` 调用数 = **0**（2026-10-02 grep 实测）。以下为**必须新增**的点位。

### 3.1 全局隐私状态（启动即查）

**位置建议**：`assets/scripts/core/` 下新建 `WxPrivacy.ts`（或并入现有入口初始化流程）

```ts
// 启动时查询是否需要隐私授权
export function checkPrivacy(cb: (need: boolean, name: string) => void) {
  const w = (globalThis as any).wx;
  if (!w || !w.getPrivacySetting) { cb(false, ''); return; }   // 非微信环境/低版本基础库，跳过
  w.getPrivacySetting({
    success: (res: any) => {
      // res.needAuthorization: 用户是否还需授权
      // res.privacyContractName: 后台配置的隐私保护指引名称
      cb(!!res.needAuthorization, res.privacyContractName || '《用户隐私保护指引》');
    },
    fail: () => cb(false, ''),
  });
}
```

### 3.2 两种弹窗方案（二选一，推荐 A）

**方案 A：使用微信官方弹窗（推荐，审核最稳）**

```ts
const w = (globalThis as any).wx;
// 在调用任何隐私接口（如广告、wx.login）之前调用
w.requirePrivacyAuthorize({
  success: () => { /* 用户同意 → 继续登录/广告等 */ },
  fail: (err: any) => { /* 拒绝 → 停止敏感采集，但游戏本体须仍可玩 */ },
});
```

**方案 B：自定义弹窗（`wx.onNeedPrivacyAuthorization`）**

```ts
const w = (globalThis as any).wx;
let resolveAuth: any = null;
w.onNeedPrivacyAuthorization((resolve: any) => { resolveAuth = resolve; showMyPrivacyDialog(); });

// 用户点「同意」
function onAgree() { resolveAuth?.({ buttonId: 'agree-btn', event: 'agree' }); }
// 用户点「不同意」
function onDisagree() { resolveAuth?.({ event: 'disagree' }); }
```

> **方案 B 合规红线**（2026 年口径，务必遵守）：
> - ❌ 禁止默认勾选「同意」
> - ❌ 禁止在用户拒绝后反复弹（同一会话最多 2 次）
> - ❌ 禁止使用含糊表述（"收集必要信息" → 必须逐项列明）
> - ✅ 必须提供「查看完整《用户隐私保护指引》」入口（`wx.openPrivacyContract()`）

### 3.3 本项目的最小接入点（3 处）

| # | 时机 | 动作 | 拒绝时的降级 |
|---|---|---|---|
| P1 | 游戏启动、进入开始页后 | `getPrivacySetting` → 若 `needAuthorization` 则弹窗 | **游戏仍可进入**，仅暂停 `wx.login` 与广告初始化 |
| P2 | 首次触发广告前（激励视频/插屏/Banner） | `requirePrivacyAuthorize` | 走既有降级：**直接发放奖励不阻断流程**（GAME.md 7.1 已定） |
| P3 | 设置页 | 常驻「隐私政策」入口 → `wx.openPrivacyContract()` | — |

> 💡 **与 GAME.md 7.1 的一致性**：已拍板「广告不可用/未配置时直接发放奖励不阻断流程」。因此隐私拒绝时的降级**天然复用这条链路**，无需新设计。这是本项目的一个结构性优势——隐私拒绝不会把玩家卡死。

### 3.4 基础库版本要求

`wx.getPrivacySetting` / `wx.requirePrivacyAuthorize` / `wx.onNeedPrivacyAuthorization` **需基础库 ≥ 2.32.3**。
当前 `project.config.json` 为 `libVersion: "widelyUsed"`（分布最广版本），需确认其实际版本 ≥ 2.32.3。代码侧已做 `if (!w.getPrivacySetting) 跳过` 兜底，安全。

本游戏为**单机本地玩法的免费游戏**，我们坚持最小必要原则，收集的信息极少：

**1. 本地游戏数据**

- **该凭证不含您的昵称、头像、性别、手机号等任何身份信息**
- **本游戏不设服务端，该凭证不会被上传至任何服务器**

- 该采集行为由微信广告平台在其 SDK 内完成，遵循微信广告平台的隐私政策
- 我们**不会**自行采集、存储或向任何第三方转让该类信息

本游戏**不收集**以下任何信息：

- 手机号、真实姓名、身份证件号码
- 地理位置信息
- 相册、摄像头、麦克风内容
- 通讯录、剪贴板内容
- 蓝牙设备信息

1. 保存并恢复您的游戏进度；

3. 向您展示广告，维持本游戏的免费运营。
