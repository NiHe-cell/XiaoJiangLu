## 0. 三条"用户特别要求核实"的直接回答

> 主理人要求明确回答的两件事，先给结论，再给依据。

### Q1：个人主体小游戏能否开通流量主（IAA）？

**答：能。个人主体开通流量主（广告变现）是合规且常见的路径，也是个人主体唯一合规的变现方式。**

| 依据 | 内容 |
|---|---|
| 微信小游戏生态资料（2026） | "**广告变现(IAA)：个人主体 ✅ 唯一合规变现路径**；虚拟支付：个人主体 ❌ 完全不支持" |
| 腾讯云开发者社区《微信小游戏完整开发指南》（2026） | "广告变现(IAA)——**个人开发者主流**；门槛：流量主需要累计 500 个独立用户访问后才能开通" |
| 微信小游戏广告变现实操资料（2026-04） | 流量主开通条件（满足其一）：① 累计独立访客 UV > 500，无刷粉、无严重违规；② 开通游戏圈且有有效活跃，发布官方贴 ≥5 篇；③ 同主体名下已有小程序满足条件一且持续变现超 1 个季度 |

**注意**：
- 流量主资格**次日刷新**，达 500 UV 后需等第二天才显示可开通。
- 另有一份资料给出更严口径（累计注册用户 ≥1000、近 7 日日均活跃 ≥100 连续 3 天）。**两套口径并存，以 mp 后台「流量主」页面当前实际提示为准**。
- **个人主体开流量主 ≠ 个人主体能上架本品类**。见 Q3 —— 这才是真问题。

### Q2：提审是否需要版号？

**答：本游戏（纯广告变现、无内购、无虚拟支付）当前口径下不需要版号。但"不需要版号"≠"不需要任何手续"。**

| 资质 | 是否需要 | 说明 |
|---|---|---|
| **游戏版号** | ❌ **不需要** | "是否需要版号，**完全取决于是否开通虚拟支付**。仅免费游戏靠广告变现，目前不需要版号；一旦涉及内购、充值、付费道具，版号是必需品，无豁免" |
| **工信部备案（小程序备案）** | ✅ **需要** | 所有小程序/小游戏均需备案，由微信平台代为向通信管理局申报。个人主体可备案，**上限 5 个小程序** |
| **软件著作权 / 电子版权认证** | ⚠️ **强烈建议办理** | 微信官方《小游戏资质提交审核指引》：软著为**选填材料**（仅牌类/捕鱼类目必填）。但多份 2026 资料指出"**接入广告变现时，广告组件审核可能要求补充软著材料**"。电子版权认证 3–5 工作日，纸质软著约 30 工作日 |
| ICP 许可证 / 文网文 | ❌ 不需要 | 本项目**无自建域名、无服务端**，不涉及经营性互联网信息服务 |
| 《游戏自审自查报告》 | ✅ **必需** | 所有游戏**必须提交**，须亲笔签名扫描件 |

> 📌 **口径分歧提示**：有一份资料称"企业主体做纯广告也要求版号"，与"以是否开通虚拟支付为准"的主流口径冲突。**本轮未能通过官方一手文档 100% 锁定该分歧**。处理建议：**在拿到正式 AppID 后，直接在 mp 后台走一次提审流程，以"上传资质"页面的实际必填项为准**——这是唯一可靠的确认方式，比任何二手资料都准。

### Q3：个人主体选不了「角色类」。本项目怎么走？

微信官方《类目设置》写明：**个人主体暂不支持选择「文化互动」「角色类」「牌类」。** 《骁将录》是卡牌 + 回合制 RPG，二级类目就是「角色」。改选休闲或把玩法改轻，都会和内容不符。

**2026-11-13 已拍板：注册个体工商户，用新的小游戏账号按「角色」提审。** 详见 §5 D1。不再在个人主体和个体户之间二选一。

## 2. 逐条详解（附证据）

> 2026-10-02 写本节时，仓库里还没有 `WxApi.ts`。下面若干「0 处 wx 调用」是当时的证据，**不是 2026-11-13 的现状**。现状看文首表格。

### C1｜微信 API（2026-10-02 时为零；2026-11-13 已接入）

- **证据**：`grep -rn "\bwx\." assets --include=*.ts` → **0 条匹配**，共 24 个 .ts 文件，5761 行代码。
- **影响**：GAME.md §7.1 已拍板的三条链路（`wx.login` 静默登录、`wx.shareAppMessage` 分享得奖励、广告变现）**全部不存在**。这不仅是合规问题，是**功能缺失**——分享裂变是微信小游戏的核心获客手段，缺失等于放弃平台红利。
- **整改**：
  1. 接入 `wx.login`（静默，不弹授权）
  2. 接入 `wx.shareAppMessage`（分享得奖励，可选不强制）
  3. 接入广告：激励视频 / 插屏 / Banner（配置表 + 完整降级）
  4. 接入 `wx.getPrivacySetting` / `wx.requirePrivacyAuthorize`
  5. 接入意见反馈入口

### C2｜无隐私授权弹窗 🔴

- **证据**：同 C1。
- **规则**：2023-10-17 起，微信隐私校验**默认全量启用**；未获用户同意前调用隐私接口会被拦截。2026 新增口径：指引需覆盖存储位置、保留期限、删除方式，且与代码实际调用**一一对应**。
- **重要澄清**：`__usePrivacyCheck__` 是**小程序 `app.json`** 字段，**小游戏 `game.json` 无此字段**（微信官方《小游戏配置》字段表 2026-10-02 核实）。不要往 `game.json` 里加。
- **整改**：见 `2-用户隐私保护指引.md` §3。
- **本项目结构性优势**：GAME.md §7.1 已拍板"广告不可用时直接发放奖励不阻断流程" → **隐私拒绝的降级天然复用这条链路**，不需要新设计。

### C3｜后台隐私保护指引未配置 🔴

- **整改**：按 `2-用户隐私保护指引.md` §2 表格逐项填写。
- **阻塞于**：正式 AppID 到位。

### C4｜无意见反馈 / 客服入口 🔴

- **核实结论**：✅ **确认需要**。微信要求游戏类目提供用户反馈/客服渠道；多份 2026 实操资料将"用户隐私协议缺失/客服入口缺失"列为高频驳回原因。同时《用户服务协议》与《隐私政策》中都必须提供有效联系方式——**目前协议里客服邮箱是空的**。
- **整改**：
  1. 设置页新增「意见反馈」入口（可跳转客服会话或展示邮箱 + 一键复制）
  2. 用户补充**真实可用**的客服邮箱/微信
- ⚠️ 注意：微信会抽查联系方式有效性，**不要填不存在的邮箱**。

### C5｜无适龄提示 / 健康忠告 🔴

- **规则**：游戏类目**强制**。健康忠告文案必须用出版署统一标准文本，**一字不可改**；适龄提示必须用标准标识（本项目建议 `12+`）。
- **整改**：见 `4-适龄提示与健康忠告.md`。
- **实现提示**：本项目零贴图，标识用 `Graphics.circle()` + `Label` 程序化绘制即可，**禁止引入外部 PNG**（违反 GAME.md §6）。

### C6｜招募概率未公示 🔴

- **规则**：含随机抽取（抽卡/开箱）玩法的网络游戏**必须公示抽取概率**。
- **证据**：24 武将 + 招募系统 → 属随机抽取；招募面板无概率展示。
- **整改**：招募面板显著位置按品质分档公示概率；**概率由配置表直接生成，禁止手填**（防止数值调整后不同步）。
- ⚠️ **本条是本轮发现的"隐藏雷"**，不在主理人初始清单里，但驳回概率很高。

## 5. 决策记录

D1 已在 2026-11-13 拍板。D2、D3、D5 仍是提审前要办的事，不是「个人还是个体户」的选择题。D4 的联系方式和执照信息等用户填写，不在仓库里编造。

### D1｜主体与类目（**已拍板：个体工商户 +「角色」**）

**事实**（仍然有效）：
1. 微信官方《类目设置》：**个人主体暂不支持选择文化互动、角色类和牌类**（developers.weixin.qq.com/minigame/introduction/guide/type）
2. 《骁将录》= 卡牌收集 + 回合制 RPG → 二级类目是 **「角色」**
3. 类目与实际内容不符会被驳回
4. 一级类目「游戏」注册后不可改；二级类目发布后不可改

**决定**：走个体工商户，用新的小游戏账号按「角色」提审。不选休闲，不改玩法。

个人主体测试 AppID 只留在本地 profiles 里做调试。正式号等个体户注册并认证后再替换 `profiles/v2/packages/wechatgame.json` 的两处 appid。公开仓库不写真实 AppID。

本项目即便换成个体工商户，变现仍是纯 IAA，不加内购或虚拟支付。版号是否因主体类型变化而被要求，仍以 mp 后台「上传资质」页的实际必填项为准（见 D2），不在代码里预埋支付。

**用户接下来要做的**：办个体户 → 认证 → 新 AppID → 两处 profiles 替换 → 备案 → 填隐私指引和客服邮箱 / 执照信息。

### D2｜版号：现在办还是不办？

- **当前口径**：纯广告、无内购 → **不需要版号**
- **风险**：若 D1 走企业主体路径，存在"企业主体纯广告也需版号"的**二手口径分歧**；若成真，版号周期 4–18 个月，**项目会停摆**
- **建议**：**不预先办版号**（成本高、周期长、且大概率不需要）。**先走一次提审流程，以 mp 后台"上传资质"页面的实际必填项为准**——这是零成本的唯一可靠确认方式

### D3｜音频策略：补还是不补？

| 选项 | 优点 | 缺点 |
|---|---|---|
| **补 BGM + 音效** | 降低"内容不完整"判定风险；显著提升留存（商业层收益） | 增加包体；需 royalty-free 素材；Audio 引擎模块不能裁 |
| **保持零音频** | 包体最小；无版权风险 | "内容不完整"判定风险；留存受损 |

- **我的倾向**：**补**。理由不是合规，是**留存**——零音频的卡牌游戏在 D1 留存上会有明显劣势，而留存是本项目唯一的验证目标。
- **约束**：必须用 **royalty-free / 自生成**音频，不得引入未经授权的素材（这是自审报告 §3 的承诺项，不能自相矛盾）。

### D4｜客服联系方式与执照信息

- 主体类型已经写成个体工商户。字号、统一社会信用代码、客服邮箱、客服微信、联系地址**继续留空**，等用户按执照和真实邮箱填写。
- 代码在 `assets/scripts/data/ContactConf.ts`。空着时设置页写「待填写，暂无法联系」，不会显示成已经能联系。
- 微信会抽查。不要填虚构邮箱或微信号。留空不能提审。

### D5｜软著 / 电子版权认证

- 提审为**选填**，但广告组件审核可能要求补充
- **建议办理电子版权认证**（3–5 工作日，成本几十至百元），先备着
- ⚠️ 若办，著作权人名称必须与小游戏账号主体**完全一致**，否则需授权书
