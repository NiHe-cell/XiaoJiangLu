## 0. 三层配置源：先分清「改哪一层」

本项目微信侧配置分散在三层，**改错层会被构建覆盖，白改**。这是本项目最容易踩的坑，先立规矩：

| 层 | 路径 | 是否被构建覆盖 | 用途 | 能不能改 |
|---|---|---|---|---|
| **A. 构建配置（永久）** | `profiles/v2/packages/wechatgame.json` | ❌ 不会被覆盖 | 存放 **appid**、屏幕方向、引擎分离、高性能模式等 Cocos 构建参数 | ✅ **这里改 appid（唯一正确位置）** |
| **B. 构建模板（永久）** | `build-templates/wechatgame/game.json`<br>`build-templates/wechatgame/project.config.json`<br>`build-templates/wechatgame/game.ejs` | ❌ 不会被覆盖（构建时被读取并输出） | 微信侧配置文件的**真源**，构建时拷贝/渲染进产物 | ✅ **这里改 game.json / project.config.json** |
| **C. 构建产物（临时）** | `build/wechatgame/**` | ✅ **每次构建全覆盖** | 上传微信开发者工具的最终包 | ❌ **禁止手改**，改了下次构建就丢 |

> **铁律**：任何微信侧配置想永久生效，必须落在 A 或 B 层；C 层只用来验证「构建结果对不对」。

## 1. 关键结论先行（给主理人）

1. **`wx****dbc8e0` 不是"模板占位"**——它是从 `profiles/v2/packages/wechatgame.json` 注入的真实 AppID。替换正式 AppID 时，**改 `profiles/v2/packages/wechatgame.json` 的两处**，不要改 `build/` 产物。
2. **小游戏的 `game.json` 不支持 `__usePrivacyCheck__` 字段**。该字段是**小程序 `app.json`** 的；微信官方《小游戏配置》字段表中无此项。小游戏的隐私授权走 **mp 后台配置《用户隐私保护指引》+ 代码侧 `wx.getPrivacySetting` / `wx.requirePrivacyAuthorize` / `wx.onNeedPrivacyAuthorization`**。详见 `2-用户隐私保护指引.md`。
3. **`openDataContext` 本项目保持留空/删除**——不接关系链排行榜，无需开放数据域。留空是合规且省包的做法。

## 2. `game.json` 逐项配置清单

微信官方《小游戏配置》支持的**全部字段**（2026-10-02 核实）：

| 字段 | 类型 | 默认 | 官方说明 |
|---|---|---|---|
| `deviceOrientation` | String | `portrait` | 屏幕方向：`portrait` / `landscape` / `landscapeLeft` / `landscapeRight` |
| `desktopDeviceOrientation` | String | - | Windows/Mac 端屏幕方向，未填则取 `deviceOrientation` |
| `showStatusBar` | Boolean | `false` | 是否显示状态栏 |
| `networkTimeout` | Object | - | 网络请求超时（ms） |
| `workers` | String | - | Worker 代码目录 |
| `subpackages` | Object Array | - | 分包结构配置（也可写 `subPackages`） |
| `parallelPreloadSubpackages` | Object Array | - | 并行下载能力 |
| `navigateToMiniProgramAppIdList` | String Array | - | 需跳转的小程序 AppID 列表，最多 10 个（基础库 2.4.0+） |
| `permission` | Object | - | 接口权限设置（如 `scope.userLocation`），客户端 7.0.0+ |
| `openDataContext` | String | - | 开放数据域目录（关系链数据） |
| `resizable` | Boolean | `false` | 是否开启大屏支持（PC 端） |

### 2.1 `deviceOrientation` —— 必须 `portrait`

- **推荐值**：`"portrait"`
- **为什么**：设计分辨率 720×1280 竖屏、fitHeight，`Canvas._alignCanvasWithScreen = true`。若误设 `landscape`，竖屏机型上画面会被强行横置，直接判「体验不可用」。
- **现状**：✅ 模板与产物均为 `portrait`，**已达标**。
- **注意**：本项目是竖屏单手操作品类，不要为了"大屏适配"开 `resizable`——开了之后 PC 端窗口可变，会破坏 9:19.5 安全区（可用设计宽 591）的布局假设。**推荐不写 `resizable`（保持默认 false）**。

### 2.2 `openDataContext` —— 留空或删除

- **推荐值**：**删除该字段**（或不填）
- **为什么**：开放数据域用于关系链数据（好友排行榜）。本项目无服务端、不做好友榜，**不需要**。留一个空串字段在产物里被剔除，说明 Cocos 已自动处理空值。
- **现状**：✅ 模板有 `"openDataContext": ""`，产物已剔除，**无风险**。
- **若后续要加排行榜**：必须新建开放数据域目录 + 在隐私保护指引里声明「关系链/好友信息」，属于新增合规项。

### 2.3 `networkTimeout` —— 本项目极小值即可

- **推荐值**：沿用现状
  ```json
  "networkTimeout": {
    "request": 5000,
    "connectSocket": 5000,
    "uploadFile": 5000,
    "downloadFile": 500000
  }
  ```
- **为什么**：本项目**无服务端、无任何自定义域名请求**（纯本地存档 + `wx.login` + 广告 SDK 自带通道）。`request`/`connectSocket`/`uploadFile` 实际不会被调用，5s 是防御值。`downloadFile` 保留 500000，给未来可能的远程资源（CDN 分包/热更）留窗口。
- **合规收益**：**零自定义域名 ⇒ 不涉及 ICP 备案**（多个 2026 资料源一致口径）。这是本项目当前最大的合规红利，别在提审前引入任何自建域名请求。
- **现状**：✅ 已达标。

### 2.4 `subpackages` —— 预留但不启用

- **推荐值**：**当前不写**（首包未超限，写了反而增加复杂度）
- **为什么预留**：微信小游戏**主包 ≤ 4MB**。当前 `build/wechatgame/cocos-js` 约 2.5MB + 其他，尚在 4MB 内。但引擎模块未裁剪，`docs/art-samples` 立绘若后续入包会迅速顶满。届时三种解法优先级：
  1. **引擎模块裁剪**（首选，零代码风险，见 §5）
  2. **资源分包**（`subpackages` 声明 + 运行时 `wx.loadSubpackage`）
  3. **CDN 远程加载**（会引入 ICP 备案成本，❌ 不推荐）
- **预留模板**（需要时再启用）：
  ```json
  "subpackages": [
    { "name": "res", "root": "res/" }
  ]
  ```
- **现状**：⚠️ 未配置（可接受），但需把「首包 4MB」设为**发布前硬闸**，见 §6。

### 2.5 `navigateToMiniProgramAppIdList` —— 不要写

- **推荐值**：**不写**
- **为什么**：本项目禁止外链跳转（GAME.md 7.3 红线第 5 条）。写了等于声明"我要跳别的小程序"，是审核风险项。**零外链是本项目天然的合规优势**。

### 2.6 `permission` —— 不要写

- **推荐值**：**不写**
- **为什么**：本项目不获取位置、不获取用户信息。`permission` 一旦声明而实际未使用，会被判"超范围声明"。**隐私保护指引与代码实际调用必须一一对应**（2026 年新增要求）。

### 2.7 `workers` —— 不要写

- **推荐值**：**不写**
- **为什么**：战斗解算是轻量回合制，24 武将规模不需要 Worker。开了 Worker 反而增加包体与审核面。

### 2.8 最终推荐 `game.json`（写入 `build-templates/wechatgame/game.json`）

```json
{
  "deviceOrientation": "portrait",
  "showStatusBar": false,
  "networkTimeout": {
    "request": 5000,
    "connectSocket": 5000,
    "uploadFile": 5000,
    "downloadFile": 500000
  }
}
```

> 相对现状的改动：**删除 `openDataContext` 空串**（产物本就被剔除，模板里留着只会误导后人以为要用）、**显式补 `showStatusBar: false`**（小游戏全屏画布，显式声明避免状态栏压住顶部 HUD）。

`build-templates/wechatgame/project.config.json` 当前内容（模板层）：

| 字段 | 模板现值 | 推荐值 | 为什么 |
|---|---|---|---|
| `description` | `"项目配置文件。"` | 保持 | 无影响 |
| `miniprogramRoot` | `"./"` | **保持 `"./"`** | 产物根目录即小游戏根 |

| `projectname` | `""`（空） | 可填 `"骁将录"` 也可留空 | 同样会被构建注入（`name: "骁将录"`） |
| `setting.urlCheck` | `true` | **提审前设 `true`** | 校验 request 域名合法性。开发期若报域名错，说明你引入了未在后台配置的域名——**这正是我们想拦的东西**，不要关掉它绕过 |
| `setting.postcss` | `true` | 保持 | - |
| `setting.minified` | `true` | **保持 `true`** | 压缩，直接关系包体与首屏 |
| `setting.newFeature` | `false` | 保持 | - |
| `setting.enhance` | `true` | 保持 | 增强编译（ES6→ES5 转译的关键开关） |
| `setting.useIsolateContext` | `true` | 保持 | - |
| `setting.es6` | 缺失 | **建议显式补 `"es6": true`** | 见下方 ES6→ES5 说明 |
| `condition` | 空模板 | 保持 | 调试条件，无影响 |

### 3.1 ES6→ES5 专项

- **结论**：本项目**不需要手动降级**。Cocos Creator 3.8 构建微信小游戏时，已通过 `enhance: true` + 构建管线把 TS/ES6 产物转译为兼容代码，产物 `build/wechatgame/src/` 下只有 `polyfills.bundle.js` + `system.bundle.js` 两个包，说明已走模块化打包。
- **必须做的验证**（不是配置，是验证动作）：在微信开发者工具「详情 → 本地设置」确认 **「ES6 转 ES5」勾选**，并在**真机（低端安卓机）**跑一遍。本地工具能跑 ≠ 真机能跑。
- **为什么在意**：`libVersion: "widelyUsed"` 覆盖的基础库跨度大，老机型 JS 引擎对 ES6 语法（`async/await`、可选链 `?.`、类字段）支持不一致。本项目 5761 行 TS 中若用了可选链/空值合并，转译不到位会白屏。

### 3.2 压缩选项

- `minified: true` ✅ 已开启。
- **补充建议**：Cocos 构建面板的 **「MD5 Cache」在提审版保持关闭**（当前 `md5=false`，✅ 正确）。开 MD5 会让资源文件名带 hash，对无 CDN 的纯本地包没有收益，反而增加排查难度。

### 5.1 现状

### 5.2 已知跨项目坑（实验室踩坑档案 `bp-cocos-pitfalls.md`）

- **必须检查**：`build-templates/wechatgame/` 与 `settings/v2/packages/builder.json` 中**不得出现任何 `E:/` 或它机绝对路径**。
- **动作**：发布前 grep 一遍 `build-templates/` 与 `settings/v2/packages/builder.json`，确认无 `E:\` / `E:/` 字符串。
- **状态**：⚠️ 本轮未执行 grep 验证（只碰 docs/，不改配置），列入整改清单**发布前必做项**。

### 5.3 首屏加载的性能闸

微信小游戏对启动性能有明确考核（2026 年口径）：

| 指标 | 建议阈值 | 本项目现状 | 状态 |
|---|---|---|---|
| 启动耗时 P90 | ≤ 5s | 未实测 | ⚠️ 需真机实测 |

### 5.4 引擎模块裁剪（包体优化，零代码风险首选）

`cocos-js` 2.5MB 中包含了大量本项目用不到的模块。**裁剪路径**：Cocos Creator → 项目设置 → 功能裁剪（对应 `settings/v2/packages/engine.json`）。

| 3D / Mesh / Model | ❌ 不用（纯 2D） | **关闭** |
| 物理（3D Physics / PhysX） | ❌ 不用 | **关闭** |
| TiledMap | ❌ 不用 | **关闭** |
| Audio（`AudioSource`） | ⚠️ 待定 | 见下 |

> ⚠️ **Audio 模块的取舍是一个产品决策，不是技术决策**：本项目当前**零音频**，但「零音频」本身是提审风险项（见 `7-审核红线与整改清单.md` 第 8 条）。若决定补 BGM/音效，Audio 模块必须保留。**裁剪前先定音频策略**。
